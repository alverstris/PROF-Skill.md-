# SASIS - Student Answer Self Iteration Scheme

## Purpose and explicit activation

SASIS improves PROF itself by generating teaching with a frozen skill revision, testing whether restricted students can use that teaching, collecting every supported issue and diagnosing all its supported causes, and evaluating warranted skill repairs. It is an explicit PROF self-iteration mode, not the ordinary document-production workflow. Activate when the user expressly requests SASIS or asks to test, iterate or improve PROF itself. A request to write, revise, improve or audit a teaching document does not activate SASIS. Merely storing or editing this scheme does not start trials. If the requested object is genuinely unclear, continue the clear work and clarify whether the user wants the document or PROF improved.

The required corpus loop is: call PROF on material A using revision r0  write document A  invoke SASIS's student questions and document probes  identify supported issues  edit and save PROF as revision r1  call the revised PROF on material B  write document B  question/probe it  revise PROF again when warranted  continue through all assigned material. A local repair/retest of A complements this progression; it does not replace the fresh run on B or justify stopping with later material unprocessed. If no issue warrants a skill edit, record that outcome and advance with the unchanged revision rather than inventing a patch.

Normal PROF author reconstruction, research, technical review, practice/help checks and rendering remain required in ordinary teaching. They are not simulated student trials. During a SASIS run the author applies normal PROF to the test documents; the student receives no skill instructions. Creating or repairing a test document alone does not show that the skill improved.

Read this reference and [the testing contract](sasis/student-testing-contract.txt) completely before planning or running SASIS and after recovery. Read [the profile manifest](sasis/profile-manifest.json) to locate the actual baseline, course evidence and source records. Do not load these mode-specific resources during ordinary teaching, including ordinary recovery. They must not silently set an actual student's starting knowledge.

## Separate roles and student restrictions

The author has the skill, original material and research. A task designer creates neutral held-out assessment questions after teaching is frozen. A student has exactly two subject-content inputs: the complete frozen baseline and visible frozen notes, with assessment questions embedded in those notes. An independent evaluator holds the reference route and audits whether the allowed passages actually license the response. These roles may be separate agents or distinct passes, but record actual separation and contamination limits. Never use the author or a source-research agent as a supposedly fresh student.

Recall within the current SASIS call is allowed: the student may remember facts, definitions and earlier passages actually supplied in this call's baseline and current document, connect them, and reuse valid deductions shown from those premises. It need not reread the same file for every question. Several questions in the same frozen condition may share that working context, but a previous unsupported answer does not become a premise merely because it was produced in the call. Consequential moves must still be traceable to the actual current inputs.

No role may use subject information recalled from outside its current authorised evidence to supplement SASIS; writing down that external recollection does not make it admissible. For the student the prohibited sources include a different document, another call/condition, other school/OCR or university knowledge, familiar definitions/formulae, conventional defaults, previous lessons/answers from elsewhere, personal/project memory, conversation summaries and pretraining. Even correct remembered OCR knowledge is unavailable unless actually supplied in the current baseline/notes or validly deduced from them. Ordinary reading, logic and arithmetic are allowed. For the author/designer/evaluator, scientific premises must come from role-authorised sources actually read or explicitly checked deductions; retaining those actually read premises within its current working session is allowed, rather than substituting external recollection. Read and verify needed research, then put any required learner premise into the teaching before freezing a new condition. An external reference can check correctness but cannot grant the student that reference's knowledge. Saved requests, queues, skill revisions and original evidence may manage/recover the experiment; they are never a third student-content input. Reopen actual evidence rather than treating a previous conversational conclusion as current authority.

Use [the student role instruction](sasis/student-role.txt) as non-content operating instructions. Supply the full baseline and notes afresh for each independent condition. Launch fresh contexts without inherited author/conversation history, personal/project memory, other trial answers, solutions, raw research, PROF/SASIS instructions, browsing or other-agent messaging. Do not pass an author recovery record or a compressed prior-learning ledger to the student. Actually present any earlier teaching needed by a multi-lecture task in its visible notes.

When using `collaboration.spawn_agent` for a student, set `fork_turns: "none"` explicitly; its default full-history fork cannot implement this boundary. Start a separate student for each different document/revision/independent condition, and retain that student's working context only for questions within its admitted frozen call. Supply the operating instruction and the two authorised content inputs without the author's conversation, suspected defect, grader route or skill/protocol text. This controls history inheritance, not technical erasure of pretraining or the shared tool/file surface; record those remaining limits.

Prefer tool-free students and technical input isolation. If tools are needed, expose only the two whitelisted read-only input artefacts and record the condition. Shared-workspace agents with broad tools provide instruction restrictions, not a technical file-access boundary. Record context capacity, complete-input delivery and room for the answer; do not invent a precise remaining budget. Split overlong notes into coherent local tasks with the baseline supplied anew. Use a larger runner or confined retrieval if the baseline itself cannot fit; do not silently truncate it or replace its premises with headings.

A fresh context cannot erase model pretraining or reveal every internal influence. Acceptance therefore requires each consequential answer move to be reproducible from a real baseline/note passage or explicit valid deduction. Unsupported rules receive no lesson-sufficiency credit even when the final answer is correct; verified unauthorised access invalidates the affected trial. Do not claim this proves human learning, retention or removal of pretraining.

Follow clear course conventions. The restricted student may flag an absent/unresolved convention and preserve supported work; it cannot supply private course facts or choose an external default. The author checks actual course evidence, and if that does not settle the choice asks the actual student/user a focused defining question and leaves dependent conclusions pending. Questions, legitimate alternative routes and honest partial attempts are valid behavior. The failure is false completeness or a route that cannot support its claimed capability.

## One document and frozen condition per student call

During explicit self-iteration, give every teaching document PROF writes or revises a document ID/revision and a separately recorded SASIS call. Bind each student call to that exact document revision, baseline revision and assessment condition. Do not let a successful call on document A stand in for a call on B, or let one call's state teach another document. Local drafts/parts receive their own applicable probes; final integrated teaching also needs its integrated checks. This does not turn ordinary document authoring into SASIS or change how lecture sessions are counted in the corpus.

Multiple questions about the same frozen current document can share one student context and lawful recall of its supplied baseline/notes. Record question order and any supported deductions reused; such outcomes are cumulative within-call evidence, not independent fresh-question results. Do not insert grader feedback, hidden solutions or teaching from outside the frozen inputs between questions; expressly authorised staged-help conditions must identify their exposed portions separately. A different document, revised document or independent control (such as missing-bridge, early-prefix or repaired-notes) requires a fresh call and the actual inputs supplied again. No answer/history from the previous call is inherited, even if two calls concern the same topic. If B needs a concept taught in A, include the actual required teaching in B's current notes; it then becomes an explicitly supplied B premise, rather than cross-document memory. Record that inclusion and its locator. Merely saying A is complete, naming a prerequisite or passing a link to A does not supply its content.

## Blocking input admission for every student condition

Before dispatching each independent condition, save an admission record that identifies the student call, document ID/revision and condition; profile/baseline revision and actual baseline hash; frozen visible notes/question boundaries and their hash; delivery method and full-input extent; runner/model configuration; available memory/history controls and their actual settings; permitted tools; context capacity/output allowance where known; and any truncation or access limits. Check the on-disk packet against the manifest, then separately establish that the complete authorised input was actually delivered or wholly available through the declared confined retrieval condition. A path, link, hash, model acknowledgement, subject title or previous read does not demonstrate delivery. Do not invent precise capacity or claim unavailable memory controls were disabled.

Use an explicit admission decision. Admit a verified full-text condition only when the complete baseline and specified notes were supplied within the runner's actual limits with room for the response. A confined read-only retrieval condition may be admitted separately when the whole baseline and notes are the only accessible subject-content artefacts; log retrieved passages and any access failure, and do not claim all text was simultaneously in context. If delivery cannot be established, keep the condition unverified and repair it before treating it as an admitted trial. If the baseline is absent, mismatched, incomplete or silently truncated, block dispatch; retain the failed admission and re-provide it in a new independently frozen condition. Do not ask the student to restore it from memory or diagnose the resulting response as a teaching gap.

Split long notes into coherent tasks containing their actual earlier teaching and supply the complete baseline anew. If the baseline itself cannot fit, use a suitable larger-context runner or the recorded confined read-only condition. Baseline-positive questions can verify particular usable operations but cannot certify full delivery or understanding of all four subjects. Baseline-only controls have the complete baseline plus visible question/data notes; they do not omit the baseline. An input failure discovered after dispatch invalidates complete-input claims and routes to delivery repair, with the original response preserved.

## Collect every supported issue before closing an iteration

The unit of diagnosis is the whole iteration, not the first failed question. Systematically audit every required source portion, document section (including later sections and help), applicable teaching obligation, administered question/response and author-workflow check. Collect every supported issue that this full audit exposes, even after finding a serious defect or an apparently decisive cause. Cover source completeness, technical correctness, prerequisites, definitions, representations, mathematical/physical warrants, method selection, connected application, interpretation, transfer, practice/help, integration, usability, underteaching and overteaching. Maintain coverage locators; sampled questions or a successful early section cannot certify the unchecked remainder. Treat unknown causes as hypotheses requiring evidence, not discovered defects.

Keep an iteration issue register with stable IDs. For every issue record the exact source/document/response evidence, all supported causes, affected instances/dependencies, classification, under/overteaching impact where applicable, required repair, any justified PROF change, and verification/status. Distinguish separate causes behind one failed answer from multiple manifestations of a shared cause; group linked instances without discarding them. Trace the earliest unsupported move within each failure to order repairs, then continue diagnosing the rest of that response and the other questions/sections. Do not use "earliest cause" as a cap on the number of issues or causes collected. Valid questions and honest partial answers remain valid behavior, with any real dependent gap separately recorded.

If an early gap prevents a student reaching later reasoning, record the later operations as untested rather than passing them by implication. Continue source and author audits of the remaining sections and use appropriately targeted independent probes without secretly supplying the missing teaching. Repair the blocking gap and revisit the later operations with fresh document conditions. Newly exposed issues join the same iteration's register; do not move them to a later material merely because the first repair succeeded.

Apply an asymmetric teaching judgement: consequential underteaching receives a substantially stronger penalty than modest additional explanation. A missing necessary premise, bridge, explanation or required coverage blocks acceptance and cannot be offset by good scores elsewhere. Also record and repair excessive reteaching of actually supplied baseline knowledge, irrelevant expansion and scaffolding that obscures the route. A short warranted connection from familiar knowledge to a new use is not overteaching. Base each judgement on the actual baseline, document and requested capability; word count and a large issue count are not substitutes for evidence. Do not remove a necessary explanation just to reduce length or add padding to create an appearance of completeness.

Close the iteration only after the full audit is covered and every supported issue has a verified repair or an evidence-backed resolution, with affected passing behavior rechecked. Regenerate affected teaching with the saved revised PROF where skill changes were warranted, re-evaluate all affected operations and dependencies, and collect/retest any new issues until this closure condition holds. A supported clarification awaiting the actual user's answer stays pending, with its dependent work unaccepted; continue unaffected checks without pretending the iteration is complete. If an external dependency prevents closure, preserve the exact pending state. Do not advance to the next material as though a partially repaired iteration passed. Do not claim that this process guarantees discovery of every possible latent error; report actual coverage and unresolved evidence honestly.

Keep the requested concise iteration change log separate from the detailed issue register. One line per iteration may summarise several PROF changes, identifying the material, incoming/outgoing revision and all changes made; if none was warranted, state that with the reason. Preserve the detailed evidence behind that line. At the end of an authorised completed corpus run, deliver the change log and final effective PROF, including its required supporting resources.

## Execute the iteration

Before the first cycle, create a complete material/coverage queue with stable IDs, actual source portions, year-level evidence and prerequisite order. Resolve what is assigned versus merely available from the user's request; do not silently select a convenient subset of required material. Several files/slides/videos for one lecture remain one material item with all required portions tracked. A long item may be processed in coherent parts, but its ID is not complete until those parts are integrated and evaluated. The author recovery record retains the entire queue; each active context loads bounded source packets and the relevant dependencies.

For each next material item, perform this cycle:

1. Record the exact self-iteration request, objective, selected profile and cases. Freeze the current skill and all relevant references/scripts, source portions, baseline, author task and generation configuration. Generate actual teaching with that revision and save its unedited output. If testing many materials or topics, preserve their required coverage and process bounded packets; do not quietly narrow the case to an easy fragment.
2. Freeze teaching before a separate designer adds neutral held-out tasks to the student's notes. Include meaning, conditions, reading/construction of representations, pivotal warrants, genuine method selection, a connected application, interpretation and a structurally changed task as relevant to the capability. Task data may supply incidental quantities or declared hypothetical premises, but must not smuggle in the very missing teaching rule being evaluated. Keep hints, solutions, grading expectations and suspected defects away from the main student input.
3. Establish matched controls from the testing contract: positive baseline checks, full notes, a genuinely necessary bridge removed, wording removed while a valid derivation survives, hypothetical alternative-rule cases, actual early-prefix teaching, unresolved conventions, and fresh repaired notes. Select controls that discriminate the concrete suspected failure and justify any inapplicable condition. Preflight surviving derivations before claiming underdetermination; where relevant, show two admissible models with different outcomes. Changing numbers alone is numerical practice, not structural transfer. Main trials have no external help; staged hints/solutions are separately frozen conditions only when expressly authorised.
4. Run fresh restricted students independently for each condition. Preserve their original answers and questions. Independently check technical correctness and then trace their consequential moves to allowed premises. Separate student restriction fidelity, lesson capability, author workflow honesty and requested artefact production. A well-founded stop can pass student behavior while exposing a lesson gap; an unsupported correct answer cannot pass the lesson. A pending convention question does not make PROF fail, but its dependent teaching is not complete.
5. Read [the question-specific rewrite guide](sasis/rewrite-guide.md) completely and perform the full audit/issue-register process above. Preserve all questions/responses and collect every supported issue across the whole document and source coverage. For each failure trace the earliest blocked operation, all supported causes and surviving valid alternatives against the admitted baseline/notes; continue through all other responses, later operations and sections. Select and perform the concrete local/structural repairs warranted by each cause, including faulty source, baseline, task, runner or evaluation components where appropriate. Save every affected passage/help/dependency and before/after locator. Recheck all repaired operations and relevant fresh structurally changed tasks using new students, add newly exposed issues, and satisfy the iteration closure gate before advancing. Preserve every original condition; a later patch cannot retroactively license an answer. Valid clarifications remain pending rather than becoming fake complete rewrites.
6. When evidence supports a skill change, edit and save a narrow PROF revision, including affected references/scripts. The next author call must load these actual revised files; do not merely write a proposed patch in a report, retain an old cached skill, or defer every edit until the corpus ends. Freeze the edited revision. Regenerate affected teaching from its original task/source conditions and compare fresh restricted-student outcomes with the original revision. Include passing cases and over-application controls, especially ordinary document work and exact brevity. A hand-patched lesson, repeated old question, wording match, unanimous AI opinion or clean ledger cannot establish general improvement in PROF.
7. Run relevant author-workflow stresses separately: many source portions; many topics and late sections; sparse or faulty sources; extraction errors; contradictory conventions; recovery/context shifts; changed prerequisites/source versions; unavailable help/tools; hostile source instructions; fabricated/stale audits; and strict product constraints. Inspect the actual teaching and coverage. A student task pass cannot certify source coverage or every unsampled capability.
8. After steps 5-7 and all resulting repair, regeneration, audit and retest loops, confirm that the full iteration closure gate is satisfied. Update the material queue with actual coverage, all issue dispositions, document/probe results and the resulting PROF revision. Only then advance to the next unprocessed material, B after A, and invoke PROF again on that material using the revised skill. Generate a fresh document and run the question/probe/issue/edit cycle again; do not reuse the previous document as though the new material was taught. Where B depends on earlier teaching from A, include the actual prerequisite passages in B's visible student notes; a remembered lesson or a completed-material ledger cannot supply student knowledge. Continue until every assigned material item and required portion has been covered and evaluated. Do not stop merely because an early item passes or several consecutive cycles suggest improvement.

After the queue is exhausted, inspect cross-material integration and any invalidated earlier checks. A later skill change can invalidate prior capability checks even if that source material was processed; recheck the affected cases and dependencies against the final effective revision. Unaffected evidence may be retained only with a substantive reason and exact revision locators. Claim completion only when all assigned material has current required evidence and no material unresolved issue. If a necessary student answer, inaccessible source, tool limit or user stopping instruction prevents this, save the queue and provide an honest partial status with the exact next item; do not mark the corpus complete. Keep candidate and installed revisions distinct and report the specific materials, observed defects, skill edits, checks and limits.

## Durable iteration records

Save run state outside the installed baseline and outside the student inputs, for example in a project-local `.prof-sasis/runs/<run-id>/`. Preserve exact requests and source locators; the complete material queue and required portions; skill/baseline/configuration digests; unedited author output; case inputs; original student outputs; withheld reference routes; independent audits; defect locations and obligation IDs; saved skill patches; retest outcomes; remaining questions; and one concrete next action. Each material row records its PROF revision on entry, document revision, actual portions covered, probe/question results, any resulting skill revision, status and evidence locators. Hashes bind evidence to revisions but do not establish semantic adequacy.

Each student condition retains its call/document/condition IDs, admission decision and actual delivered inputs. Retain the full iteration issue register, coverage evidence, closure decision and concise change-log entry across recovery. Each repair retains all supported causal diagnoses, affected instances, question types, chosen rewrites, changed passages/dependencies, any PROF rule changes and fresh evidence. An author record may point to a baseline file, but the student must receive the actual permitted input again. No summary, answer or source conclusion carried from outside the current role-authorised inputs may fill a missing content premise. Recall and valid deduction within the current supplied call remain allowed; the record must not turn them into knowledge transferred to a different student call.

After interruption or compaction, the author reloads SKILL.md, this protocol, exact current instructions, the active run record and affected original artefacts. Fresh students receive their baseline and notes only. Propagate invalidation through changed teaching, help and prerequisites; missing evidence remains unverified. Keep old conservative-baseline or advanced-course trials under their original conditions, not as passes for this OCR/year 1 profile.

Stored resources and successful installation establish that SASIS is available, not that its experiments have run. Mechanical validators, routing probes, student simulations and human learner outcomes are separate evidence categories. Report which actually occurred.
