# Additive evidence publication path adaptation

This procedure changes repository target names only. It neither edits nor renames a local source, changes a raw blob, modifies the five approved package overlays, alters package or reader controls, or reruns a failed synthetic reader.

1. Verify the original publication index against SHA256 `4b0ff7587f59528b8a84e91f253ea7b14909de7bb708c28728a1b673080b0987` and its frozen preparation seal. Read root's exact original tree-rejection record without changing it. Require its 204 affected path/blob identities to equal the index entries whose target contains an exact `.git` component.
2. Select `_git_metadata_snapshot` as the replacement component only after confirming no original target already contains that exact component. Replace exact slash-delimited `.git` components, leaving every other component in its original order. Names such as `.github` or `archive.git` are not transformed.
3. Require injective complete targets, case-folded uniqueness, no file/ancestor conflicts and no invalid relative-path components. Reverse the reserved replacement component back to `.git` and require exact equality to each original target. Require the five root overlays and all 36 complete-package inventory entries to remain unchanged.
4. Preserve all 3,797 original items, raw source paths, byte lengths, SHA256 and Git blob IDs. Store each original target in `original_path`; write a separate mapping for all 204 changed paths. Recheck every original item and package source byte. Preserve the original 398 unique blob identities in their original order so root can reuse those already uploaded blobs.
5. Append the ten explicitly listed adaptation evidence records under the new `publication-path-adaptation/` evidence target. These include the exact root failure record, exact controlled diagnostic record, mapping, local validation result, reusable validator, procedure, README, reproducible preparer, unchanged transport helper and adaptation record. Include these new bodies in unique-blob transport. Do not omit an existing evidence item.
6. Root independently reviews this new index, mapping, seals and raw identities. Root constructs a tree from the same pinned base tree using the mapped entries and additions only; no deletion entries are supplied. Root owns publication and must verify the actual API response and immutable readback. The earlier rejected tree attempts created no accepted tree, commit or ref update according to the retained root record.

Root separately performed a controlled actual GitHub probe: identical base tree, body SHA, mode and type, with only `.git` changed to `_git_metadata_snapshot`. The original component rejected with 422; the mapped component returned immutable tree `69de497b6d0162394442381c0d84477c07657eb4`. No commit or ref changed. This confirms the component diagnosis without establishing acceptance or publication of the full adapted tree. `github-path-component-diagnostic.json` preserves the exact root record bytes.

`validate_evidence_paths.py` supplies reusable path-shape and target-set checks. Its known `.git` component rejection follows the controlled root probe, while its relative-path, duplicate, case-folded and ancestor checks prevent ambiguous packaging. It is not an exhaustive guarantee of every server-side GitHub condition. No API mutation is performed by this adaptation preparer.

The original local publication index and all source seals remain authoritative for their original bytes and original target names. Synthetic inventories and logs still contain their original local `.git` paths; consumers resolve those historical target names through `target-path-mapping.json` when locating the published snapshot. Contents are not rewritten to pretend their historical paths changed.
