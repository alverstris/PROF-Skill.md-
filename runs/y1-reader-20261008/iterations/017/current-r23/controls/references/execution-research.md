## Host guidance and actual implementation boundary

[Official skill documentation](https://learn.chatgpt.com/docs/build-skills) states that discovery begins with name/description, that the full SKILL.md is loaded on selection, and that implicit selection matches the description. It also warns that long descriptions can be shortened in the initial catalogue. The revision front-loads teaching authoring/continuation scope and preserves `allow_implicit_invocation: true`. Metadata is discovery support, not proof of execution or a release lock.

[OpenAI's long-horizon Codex example](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex) describes externalized specification, plan, status and repeated validation. It is an engineering example involving coding, not a controlled teaching study. The recovery index, sharded topic state and checkpoint loop are analogous design choices; no host hook or runtime customization is installed here.

The bundled helper independently reads local file bytes to detect stale recorded digests, missing topic files, unread declared portions, unresolved recorded gaps and absent evidence locators. Its assertions are bounded by the declared manifest and authored records. It cannot infer an omitted required topic, verify a web-reading claim, authenticate a waiver, assess the quality of a proof or hint, or prevent an agent bypassing the tool. A trusted external release mechanism would require a separately authorized host integration and semantic evaluation; this skill does not supply one.
